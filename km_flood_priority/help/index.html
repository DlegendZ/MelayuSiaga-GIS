KM Flood Priority

Verification priority based on recorded flood events at RW scale in Kelurahan Kampung Melayu, Kecamatan Jatinegara.

No recorded event (≠ safe). Missing verified access evidence produces UNKNOWN. The plugin does not simulate inundation, predict future events or certify evacuation safety.

Run the full pipeline

  1. Install the ZIP through Plugins → Manage and Install Plugins → Install from ZIP.
  2. Open KM Flood Priority → Run full pipeline… or find kmflood:run_pipeline in the Processing Toolbox.
  3. Select RW, roads, safe-point evidence and kelurahan boundary layers from your prepared inputs.gpkg; select the canonical event CSV and source registry CSV.
  4. Keep the documented thresholds, select a new output GeoPackage and run. Safe points and dated closures are optional; omission produces UNKNOWN access.
  5. Inspect priority, validation issues, access and run metadata. Open the result in a fresh project to check the embedded styles.

Algorithms

Processing IDInputs → outputs
kmflood:import_validateCanonical CSVs, source registry and RW units → normalized events, retained duplicates, validation issues and summary. Row errors are excluded and reported; schema errors or zero valid rows stop processing.
kmflood:test_accessRW units, roads, point targets and verified dated closures → access by RW/date, routes and graph stats. Empty EVENT_DATES means baseline; ALL uses closure dates.
kmflood:compute_priorityNormalized events, optional access/scenario list and thresholds → priority polygons and table with an unassigned summary.
kmflood:export_packageAnalysis outputs, context and sources → eleven-layer GeoPackage with default styles and run metadata.
kmflood:run_pipelineAll important inputs → the four child algorithms and result package. Blank EVENT_DATES uses imported dates.

Default class rules

Countable records have known RW, accepted location confidence and no cross-source duplicate marker. Distinct dates with gaps of at most two days form one episode. Maximum recorded depth remains separate from recurrence.

ClassRule, evaluated in order
NO_RECORDZero countable records.
HIGHAt least 3 episodes, plus either maximum depth ≥50 cm or CUT_OFF access.
MEDIUMAt least 2 episodes, maximum depth ≥50 cm, or CUT_OFF access.
VERIFYRemaining recorded units; weak evidence needs checking.

Dashed outlines mark field-check needs. Hatch marks VERIFY; a dotted pattern marks NO_RECORD. Labels show episode counts. Scenario flags never alter classes. Shared source totals cannot be summed over exploded RW copies.

The accepted 2025 working set has RW 04/05 HIGH (16 episodes each), RW 07/08 MEDIUM (one episode each), and five NO_RECORD units. RW 04/05 share the same 25 source rows for Jl. Kebon Pala II, RT 12–13 in RW 04 and RT 10–11 in RW 05. Do not add their episode counts or infer whole-RW inundation. Without Genangan, RW 04/05 remain HIGH with 15 episodes each; nine threshold combinations change no class. All access is UNKNOWN.

Access results

The undirected pedestrian graph uses road vertices rounded to 0.01 m. RW point-on-surface origins and targets snap to vertices within 50 m by default. One-way vehicle restrictions are ignored. Verified closures remove matching OSM IDs or normalized road names for the exact date.

REACHABLE requires dated verified closure evidence and a path to usable target evidence. CUT_OFF requires that evidence and no path. Missing targets, off-network origins, baseline-only runs and dates without verified closures yield UNKNOWN. Including unverified targets flags the result and does not verify them.

Green lines are reachable event paths; dashed grey lines are baseline paths. Red crosses on RW origins show CUT_OFF evidence. Zero-distance paths retain their distance/status row and have no line geometry.

Provenance and troubleshooting

CSVs are UTF-8, comma-separated; dates are ISO YYYY-MM-DD. Every source ID must be registered. Missing CRS, invalid geometry, duplicate RW IDs or missing fields require input correction. All spatial outputs use EPSG:32748.

events.notes preserves source verification and inconsistency notes. Unassigned evidence stays out of RW polygons. run_info records versions, UUID, UTC timestamp, parameters and actual event years.

Use a new filename or explicitly enable OVERWRITE. Exports include default styles. The plugin has no extra runtime Python dependencies and performs no network requests.
